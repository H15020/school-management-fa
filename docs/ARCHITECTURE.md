# معماری فنی

## هدف
ساخت یک اپلیکیشن اندرویدی آفلاین‌محور برای مدیریت مدارس ایرانی، با امکان استفاده مستقل از اینترنت و همگام‌سازی داده‌ها در صورت فراهم بودن زیرساخت ارتباطی.

## معماری لایه‌ای
1. **Presentation:** صفحات Jetpack Compose، وضعیت صفحه و ViewModelها.
2. **Domain:** مدل‌های دامنه، قوانین کسب‌وکار و Use Caseها؛ بدون وابستگی به Android UI.
3. **Data:** Repositoryها، Room DAOها، نگاشت مدل‌ها و صف عملیات همگام‌سازی.
4. **Infrastructure:** رمزنگاری، پشتیبان‌گیری، زمان‌بندی کارها و ارتباط شبکه‌ای اختیاری.

جریان اصلی داده:
UI ← ViewModel ← Use Case ← Repository ← Room

جریان همگام‌سازی آتی:
Room → صف تغییرات → سرویس همگام‌سازی → سرور اختیاری

## اصول آفلاین
- عملیات اصلی ثبت و مشاهده باید بدون اینترنت کار کند.
- هر تغییر قابل همگام‌سازی، شناسه یکتا و زمان ثبت داشته باشد.
- قطع ارتباط نباید باعث از دست رفتن اطلاعات ثبت‌شده شود.
- تعارض تغییرات باید با سیاست مشخص و قابل ممیزی حل شود؛ آخرین‌نویسنده به‌تنهایی برای همه داده‌ها سیاست مناسبی نیست.

## چندمدرسه‌ای و چندساله
- هر رکورد سازمانی باید به شناسه مدرسه وابسته باشد.
- داده‌های هر سال تحصیلی با شناسه مستقل نگهداری شوند.
- بستن سال تحصیلی به معنی حذف سوابق نیست.
- انتقال دانش‌آموز یا ساخت سال جدید باید عملیات صریح و قابل ثبت در گزارش ممیزی باشد.

## سازگاری و وابستگی‌ها
- حداقل نسخه Android: API 26 (Android 8).
- رابط کاربری: Kotlin و Jetpack Compose.
- ذخیره‌سازی محلی: Room 2.6.1.
- از وابستگی اجباری به Google Play Services، Firebase و ورود گوگلی پرهیز می‌شود.
- کتابخانه‌ها باید از مخازن عمومی قابل دسترس و قابل دریافت باشند.

## امنیت
- حداقل‌سازی داده‌های شخصی ذخیره‌شده.
- نگهداری کلیدهای رمزنگاری با Android Keystore.
- پشتیبان رمزگذاری‌شده و امکان بازیابی کنترل‌شده.
- ثبت رویدادهای حساس در Audit Log.
- کنترل مجوز در لایه Domain و Repository، نه صرفاً پنهان‌کردن دکمه‌ها.
- نسخه فعلی هنوز ورود کاربر، مشتق‌سازی امن رمز و رمزنگاری پایگاه داده را پیاده‌سازی نکرده است.
